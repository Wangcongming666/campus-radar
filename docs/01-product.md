# 产品范围与业务规则

## 1. 交付定义

校招雷达是大学生求职工作台，覆盖发现岗位、记录投递、准备面试、管理学习与比较 Offer。默认中文，展示时区 Asia/Shanghai，可在设置修改。

用户指定：Java/JDK 21、React、MySQL、MyBatis-Plus、RabbitMQ、Redis；前端页面完整复刻；结构精简。当前已实现完整页面与后端业务。

前端完整包括独立路由、页面内容区、导航、弹窗、抽屉、筛选、拖拽、表单、主题、动效、移动端及 loading/empty/error/unauthorized/success 状态；按钮必须产生可验证结果。开发未完成的能力明确标为未完成，不把 Toast 当实现。

## 3. 角色与内容

- 游客：读取已发布岗位、公司、面经、题目、宝典、匿名薪资聚合、已发布社区/内推/情报。公共页面可用工作台外观；不因整个壳层而强制登录。
- USER：操作本人投递、收藏、文件、笔记、练习、订阅、日程、Offer；发布内容进入审核。房间成员和内推参与者按关系授权。同路人候选仅展示主动开启buddyDiscoverable的用户昵称、方向和城市。
- REVIEWER：读取待审内容、做审批、处理举报；不能任意读取私人简历、录音、笔记或提升角色。
- ADMIN：管理公共资料、提供者认证、服务状态和任务重试。用户私有资源仍按明确授权访问，管理员身份不默认获得附件下载权限。

公开内容状态 DRAFT → PENDING → PUBLISHED / REJECTED；PUBLISHED 可 HIDDEN，下架即时影响详情、搜索与缓存。作者修改正文后回到 DRAFT 或 PENDING，旧的已发布正文不继续悄悄更新。个人中心保留成就展示，按首次收藏/投递/完成练习等真实事件派生，显示规则与首次达成时间，不用虚构徽章。公司基础资料由管理员直接维护并记审计；岗位招聘状态 OPEN/CLOSED/UNKNOWN 与发布审核状态分开。

### 角色职能边界

| 身份 | 职能 | 不允许 |
| --- | --- | --- |
| 游客 | 浏览已发布的公开岗位、企业、面经、题库等内容 | 写入个人或管理数据 |
| USER | 求职、收藏、简历、投递、日程、面试、学习与个人进度；投稿后提交审核 | 访问管理接口、修改账号角色或审核发布内容 |
| ADMIN | 用户基础资料及普通账号状态管理；企业、岗位、来源、题库、宝典、情报维护；策展面经；审核、举报、服务和审计 | 使用求职者的投递、简历、练习等接口；读取用户私人笔记/附件；冒用用户作者身份；通过普通用户管理接口创建管理角色或更改密码 |
| REVIEWER | 内容审核与举报处理；读取已提交的待审内容 | 求职操作、用户管理、服务管理、管理目录写入或角色变更 |

管理员不兼任求职用户。前端登录默认进入管理后台，管理导航与求职导航分离；后端根据 API 合同与数据库实时身份统一鉴权，未登记的接口默认拒绝。共享账号资料、账号安全与主题设置不属于求职功能。

用户管理仅投影必要基础字段，账号冻结/停用增加会话版本，撤销既有登录；不可借此跳过注销流程，不能冻结管理账号或提升角色。用户投稿的 DRAFT/REJECTED 不进入管理员面经目录；PENDING/PUBLISHED/HIDDEN 可查看并审核/下架，不能直接改写或删除作者内容。管理员自行整理的面经作者为空，走独立策展维护与审核。

## 4. 核心规则

### 4.1 岗位与来源

- 岗位只能来源于人工审核录入、原创或明确获准的内容。首期不实现爬虫、自动投递或外部招聘系统同步。
- 同一来源规范化URL的SHA-256唯一；原URL仍保存供跳转。未知薪资/学历/发布日期/截止日期保留 null 或 UNKNOWN；不能填0、当前时间或虚构JD。
- 截止时间 EXACT 保存 UTC instant；DATE 保存来源时区的日期，显示“当日截止”；UNKNOWN 两者为空。DATE 在排序时按来源时区次日00:00的排他边界计算，不伪装为精确秒。
- 官方外链点击只打开网址，不改变投递阶段。所有链接只允许 HTTP/HTTPS；站内回跳仅接受本站路径。
- 多维筛选 AND，同维多个值 OR；翻页和排序由服务端执行，不整包下载目录再筛。

### 4.2 投递与面试

八阶段：PENDING 待投、APPLIED 已投、ASSESSMENT 笔试、INTERVIEW_1 一面、INTERVIEW_2 二面、HR HR面、OFFER Offer、CLOSED 结束。允许跳阶段和回退，变化留事件。

- 同账号同岗位只有一条投递；重复加入返回已有记录，归档记录不会因此自动恢复。
- 归档可恢复，不等于删除。进入 CLOSED 必填 REJECTED/WITHDRAWN/EXPIRED/ACCEPTED/OTHER；离开后清空结束原因与结束时间。
- 用户显式填写 appliedAt；不根据浏览或阶段变化伪造投递日期。
- 移动和撤销核对卡片version与boardVersion。仅可撤销本人最近10分钟内且未被后续操作改变的最新事件；撤销追加反向事件。
- 看板最多展示500条；截断时提示筛选/归档，并禁用排序操作，避免对不可见全量卡片误排。
- 面试轮次是事实记录，不与8阶段强制一一对应。轮次修改在同事务维护日程投影；同一轮次只有一条日程，不能从两入口各保存一份。
- 时间冲突条件 startA < endB AND endA > startB，只检查SCHEDULED状态；时段接触边界不冲突，提示冲突不阻止用户保存。

### 4.3 文件、知识与规则工具

- 简历支持 PDF/TXT/MD，10MiB；音频MP3/WAV/M4A/WebM，30MiB；头像PNG/JPEG/WebP，2MiB；备份ZIP，100MiB。后端校验MIME和文件头，文件位于私有存储。
- PDF浏览器Canvas预览；可提取文本的PDF解析文字，扫描版显示“未提取到文字”，支持手动补充，不承诺OCR。
- 简历版本新增而不覆盖原件；每账号最多一个默认版本。文件仍被业务引用时拒绝删除，关联简历属于本人。
- 题库练习使用真实已发布题目及题目/答案快照；无题目不生成伪题。服务端计时，暂停/恢复/提交为条件更新，提交后不能继续写答案。
- 匹配、诊断、重点提炼和反馈都是可解释规则，显示ruleVersion、依据和限制。不接外部LLM、向量检索、云端转写或生成式面试官；音频只回放和手动转写。
- 私有题目掌握度、章节笔记与公共内容分表。新版章节不覆盖私人笔记，返回contentVersion供提示。

### 4.4 成长、统计与协作

- Offer年现金=月薪×明确薪资月数+明确现金奖金；任一必要项未知则年现金为null；股权独立展示，不默认折现。
- 比较维度评分0–100，权重非负且至少一项>0；按有效维度归一化，缺失不按0计算，同时显示覆盖率；不凭低覆盖率宣布绝对最优。
- 薪资只展示审核后匿名聚合；样本少于5条时分位与中位数均隐藏，显示数量与不足说明。
- 统计时间窗以用户时区日期边界转UTC，使用半开区间[from,to+1day)。appliedCount为appliedAt落窗的唯一投递数，interviewCount/offerCount为该批投递曾进入对应阶段的唯一数量。分母0比率为null。撤销事件成对抵消，历史趋势不把拖回阶段重复计数；归档默认纳入历史。
- 订阅按subscriptionId+jobId+jobVersion去重，用户停用后不再生成新命中；邮件发送前再次查偏好。
- 内推申请只有申请者与有效提供者可读；提供者不能申请自己的资源；只有提供者能接受/拒绝，申请者只能取消PENDING。记录受理不等同企业已接收简历。
- 加入房间、接受邀请在锁定房间行后核对容量和有效期；只有房主能创建共享任务/邀请/关闭房间；成员只能更新自己的进度；退出立即失去成员内容访问。
- 公开动态、面经、内推、薪资和情报需审核；社区与面经评论/回复直接发布，可由作者撤回，管理员可删除并审计，举报仍可提交。撤回/删除清除正文并保留回复关系；评论父节点必须属于同一公开主题；外部内容不通过前端HTML直接渲染。

## 5. 非功能目标与范围外

目标而非已测结果：360/768/1024/1440px适配；正文对比度4.5:1；键盘可操作核心流程；尊重reduced-motion。10万岗位、20并发读的列表API p95≤500ms；p75 LCP≤2.5s、INP≤200ms、CLS≤0.1。性能需要按09定义的环境实测。

首期不接支付、短信、第三方OAuth、即时聊天、外部日历双向同步、全网采集。邮件选择SMTP；缺内容显示空态；本机数据库测试内容按用户授权创建，统一标注SYNTHETIC或“测试”，可在管理员后台删除，不进入生产。前端运行时只读取后端数据，不提供硬编码演示或本地虚拟数据回退。本项目使用独立业务库，已有业务数据继续保留。


## 6. 规则计算合同

这些规则只辅助准备与比较，分数不是录用概率或技术正确性判断。每次返回带固定ruleVersion；改规则必须升级版本并更新测试样本。

| 工具 | 可直接实现的v1规则 |
| --- | --- |
| 岗位匹配match-v1 | 岗位明确届别/招聘类型与用户偏好冲突为硬条件不符，score=0并列理由。其余维度为方向30、城市20、学历20、关键词30；双方信息已知的维度才进入分母。方向/城市按集合交集0或1；学历按ASSOCIATE/BACHELOR/MASTER/DOCTORATE序比较，ANY为满足，UNKNOWN不计；关键词为岗位skills在本人默认简历文本中的去重命中比例，英文不区分大小写、中文按完整技能词。score=100×有效维度加权和/有效权重，coverage=有效权重/100×100；权重为0时score=null，返回缺失字段。硬条件未知不擅自判不符。 |
| 简历检查resume-v1 | 教育/项目或经历/技能三类结构缺失各扣15；有目标岗位与skills时按未覆盖比例最多扣30；单行超过300字符扣10；扣分最低0。没有文本则score=null并提示手动补充，不从空PDF判断用户能力。每项返回原文证据/缺失规则、建议，不生成经历。 |
| 练习报告mock-v1 | score仅取用户已给出的selfScore算术平均，未自评全部为null；单题展示是否空答、字数与用户自评，STAR仅检测情境/任务/行动/结果标记并提示表达结构，不据此判技术对错。参考答案快照独立展示。 |
| 规划plan-v1 | targetDate必须晚于当前用户日期；先取未来最多28天，将每周可用小时拆成每项30分钟，最多100任务。按基础学习40%、项目准备30%、岗位投递20%、复盘10%分配，分配余数按该顺序补齐；任务含实际日期/方向/里程碑。generation_key由规则版本+目标日+方向排序+时间预算+任务序号生成，重复生成只补缺失任务，保留用户已有任务及状态。 |

看板stats按当前筛选后的全部未归档记录统计，不按500条截断列表统计：total为总数，applied为appliedAt非空数，interviewing为当前INTERVIEW_1/INTERVIEW_2/HR数，offers为当前OFFER数。个人概览interviews为未来SCHEDULED轮次数，offers为本人未过期且PENDING/ACCEPTED的Offer数。成就从当前保留的收藏、投递和已完成练习记录派生；全部相关记录清空后相应成就消失，不额外保存无法核验的永久历史。

公开讨论的角色入口：USER可发表/回复，只能撤回本人评论；ADMIN可只读浏览社区和面经，并撤回任何人的公开评论（必须填写原因、走管理接口审计）；REVIEWER/匿名不展示评论写入或撤回操作。允许管理身份访问公开讨论不授予私人投稿、投递或学习数据权限。
