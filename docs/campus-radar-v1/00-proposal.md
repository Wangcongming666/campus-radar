日期：2026-10-23。状态：用户已确认并进入实现。当前交付与验证结果见 [08 交付状态](08-delivery-status.md)；未恢复已有删除文件、未部署生产。

2026-10-24 范围更新：用户取消外部AI、embedding推荐与云端转写，保留规则工具和题库模拟练习。对应PRD与架构已更新，数据库保持原定结构。

## 交付与决策

1. 推荐：模块化 Next.js 单体 + Python 异步 worker + PostgreSQL/pgvector。业务闭环集中，异步任务独立扩容；第一阶段不引入微服务、Redis 或独立搜索集群。
2. 备选：Next.js + 独立 FastAPI 全业务后端。跨端复用更直接，但引入双重鉴权与 API 开发成本；当前无原生客户端需求，不采用。
3. 备选：纯前端演示。视觉验证最快，但无法承担真实数据、投递保存与异步任务；只作为推荐方案中的 mock 数据模式，不作为最终架构。

推荐部署组合为 Vercel + Railway + Supabase（Auth、PG、Storage）；Fly.io、Neon 是迁移备选，不同时开发两套生产适配。部署与付费服务开通不在本次文档交付内。

## 两条交付线

- UI 预览线：确认方案后，先搭全站壳层与所有独立路由，使用一致的 mock 数据贯通页面。V2/V3 的预览可交互，但持续显示“演示数据”，不计入 MVP 业务验收。
- 业务上线线：按 MVP → V2 → V3 对接 API、鉴权、数据和 worker。生产导航只展示已验收能力；未开通路由有清晰的阶段说明与返回入口。演示入口独立提供完整产品预览。
- 每个阶段先完成该阶段的 UI 状态与交互，再接真实数据；MockAdapter 和 HttpAdapter 使用同一接口合同。
- 第一轮开发顺序：设计系统/壳层 → 全路由 mock 预览 → 岗位闭环 → 看板闭环 → 面经/宝典 → MVP 后端与爬虫 → 验收。

## 已确认的基线

默认中文、Asia/Shanghai、国内高校应届生；首批方向为前端/后端/算法/产品/设计，筛选维度可扩展。MVP 主闭环为发现岗位 → 收藏/加入待投 → 记录阶段 → 阅读面经/宝典；没有简历也可使用。真实个人数据不进入 mock 模式。所有模拟数据、实时信号、评分与 Offer 墙都有明确来源或演示标记。

本基线与 MVP 边界已确认，已有全站演示可验收；真实上线前仍需完成 08 文档列出的配置与接线。
