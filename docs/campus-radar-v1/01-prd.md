# 01 PRD 轻量初稿

版本：0.2；更新：2026-10-24；状态：已确认，用户已取消真正的 AI 能力；实现与上线边界见 08-delivery-status.md。

## 已确认的范围调整（2026-10-24）

外部 LLM、embedding 语义推荐、生成式模拟面试/报告和云端语音转写退出当前产品范围，不计入待完成项，也不要求模型密钥或模型费用。保留基于偏好/关键词的规则匹配、正文重点提炼、简历文字提取与规则检查、题库驱动模拟练习、自评与规则反馈、录音回放和手动转写；页面明确说明反馈依据，不称作 AI 推理。题库练习仍需真实题目内容。

已有 PostgreSQL、数据卷、pgvector 扩展与可空预留字段保留；不为这次范围调整执行数据库迁移或生成向量。

## 定位与画像

校招雷达面向大学生，连接岗位发现、投递追踪、面试准备和长期成长。核心价值是减少信息分散与流程遗忘，让用户知道现在投什么、进展到哪一步、下一场如何准备。

| 用户 | 当前困难 | 首要任务 |
| --- | --- | --- |
| 大三/研二准备期 | 校招时间不清楚，知识准备无结构 | 看岗位要求，建立准备清单 |
| 应届集中投递期 | 多公司阶段混乱，DDL 遗漏 | 筛选岗位、统一记录投递 |
| 面试密集期 | 面经碎片化，复盘不连续 | 按公司岗位找经验，追踪面试 |
| 多 Offer 决策期 | 薪酬口径不同、主观偏好不清楚 | 标准化比较，明确个人权重 |

## MVP 边界：验收以此表为准

MVP 是“岗位 → 投递看板 → 面经/宝典”可持久化闭环，不承担全功能生产上线。全路由 mock 预览是独立的产品展示交付，不能替代生产业务验收。

| 阶段 | 纳入能力 | 明确限制 |
| --- | --- | --- |
| MVP | 落地页、邮箱登录注册、基础引导、岗位列表/详情、公司基本资料与在招岗位、8 列看板、面经列表/详情、宝典、基础收藏、全局搜索、个人概览、基础设置 | 搜索覆盖岗位/公司/面经/宝典；题库只在全站预览中可搜索；匹配分只演示；公司只提供基本信息与岗位标签页 |
| V2 | 偏好/关键词规则匹配、简历文字提取及版本库、订阅/推送、内推、日程、统计、面试时间线/复盘、面经重点提炼、题库、公司风格/面经包、规划、薪资、通知中心、面经发布/评论 | 录音须明确授权，转写以手动输入为主；薪资与开奖信息须标样本、时间和可信度 |
| V3 | 题库模拟面试、规则简历检查、社区、同路人/组队、情报雷达、Offer 决策、完整公司情报/评价/避坑、成就体系、关键词知识检索 | 反馈展示规则依据；社区需举报、审核及删除链路 |

### MVP 功能明细

- 岗位：关键词、城市、公司、方向、学历、招聘类型、届别筛选；最新/截止排序；列表/卡片/表格；无限加载与“加载更多”备用入口；收藏；来源外链；Drawer；详情 JD；DDL。
- 看板：待投/已投/笔试/一面/二面/HR 面/Offer/结束，拖拽及键盘移动；卡片新增、详情、笔记、归档；公司泳道；同列顺序；阶段变更历史；顶部统计。用户通过官方链接自行投递，再手动记录状态。
- 面经：合规提供的授权摘要或用户授权全文；关键词/公司/方向/轮次筛选；瀑布流视觉但 DOM 顺序保持自然；Drawer/详情/目录/收藏；MVP 不开放发布与评论。
- 宝典：方向→章节目录；八股文、项目深挖、STAR、反问；章节搜索、锚点、私有笔记与完成进度。
- 基础设施：暗亮主题、响应式导航、Cmd/Ctrl+K、搜索分组、Toast、错误重试、骨架、独立空状态、404、演示标记。
- 账户：邮箱注册/验证/登录/登出；身份与偏好保存；账户删除、本人数据导出。引导允许跳过简历，生成基于规则的准备时间轴；简历采用浏览器文字提取与用户确认。
- 数据：MVP 接入最多 2 个经过准入确认的公开岗位来源；授权面经种子、原创宝典；来源不足时保留真实空状态，不混入假岗位。

## 用户故事与验收

| 用户故事 | 可验收结果 |
| --- | --- |
| 我只想看适合届别和城市的岗位 | 筛选反映到 URL，刷新/返回保留；清空筛选可恢复；无结果显示对应引导 |
| 我想快速比较几个岗位 | Drawer 支持 ESC 关闭和焦点回归；“查看详情”到独立路由；返回恢复滚动位置 |
| 我想记录某岗位的投递 | 重复添加返回现有记录；保存后刷新仍存在；官方投递外链不会自动标为已投 |
| 我想移动投递阶段 | 拖拽和菜单移动效果一致；可撤销；保存失败回滚；两标签页冲突提示刷新 |
| 我想准备明天的面试 | 从岗位/公司找到对应面经和宝典；缺少对应内容时提供方向内容及明确说明 |
| 我想保存学习记录 | 笔记只对本人可见；保存状态明确；离线或失败时保留编辑内容供重试 |
| 我不想注册也想先了解 | 公共内容可浏览；收藏/加入看板才要求登录，并返回原操作位置 |

## 成功指标

- 核心激活：首次访问后 24 小时内完成“筛选岗位 + 保存一条投递/收藏”。统计访问→详情→保存的转换，不把导航点击算投递。
- 留存：7 日回访、每周有效阶段更新、面经/宝典有效阅读。
- 数据质量：来源覆盖、采集成功率、重复率、失效岗位率、最后验证时间；人工抽检不以数量替代质量。
- 练习质量：有效完成率、用户有用反馈和失败保存率；规则分数不作为真实录用概率。
- 基线建立后再设增长目标，不在初稿虚构运营指标。

## 非功能验收目标

- 性能：生产测量 p75 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1；参考设备为中档移动设备/4G。MVP 列表 API 在 10 万岗位、20 并发读取的压测集下 p95 ≤500ms（不含第三方服务）；这些是目标，不是已测结果。
- 可用性：360/768/1024/1440px 验证；键盘可完成核心操作；图表提供文本摘要/表格；正文对比度目标 4.5:1；支持 reduced-motion。
- 安全：每个读取/写入端点校验身份与资源归属；Cookie 会话、CSRF/Origin 检查；私有表 RLS；输入验证、富文本净化、速率限制、密钥仅在服务端。
- 数据：UTC 存储、按用户时区展示，默认上海；未知 DDL 不显示倒计时；日期精度明确；未知薪资不显示 0；删除账户后清除私有数据与异步任务载荷，备份按保留策略到期。
- 合规实施要求：逐来源核验访问规则、使用授权与 robots；面经不默认全文搬运；不采集登录墙、私人联系方式；提供来源标注、纠错和删除渠道；简历与录音仅在同意后处理，不发送至外部模型。
- 运维目标：月可用性目标 99.5%；每日备份，目标 RPO 24h / RTO 8h，上线前以恢复演练确认；任务重启可恢复、重复执行不重复入库。

## 不做清单

全产品不做外部大模型接入、embedding 生成与向量推荐、生成式面试官/报告或云端转写；这些能力已由用户取消。

MVP 不做自动投递、验证码/登录墙绕过、付费内容抓取、付费内推交易、录音/语音、真实 AI 匹配、AI 生成报告、社区发帖/聊天/组队、第三方推送、全网覆盖承诺、录用概率承诺。公司泳道不是公司 CRM。看板 Offer 阶段不等于已接受 Offer。

## 验证策略

先验收所有独立路由和 mock 状态，再验收 MVP 真数据闭环。核心 E2E 覆盖登录回跳、岗位筛选/收藏、添加投递/拖动/撤销/冲突、面经详情与宝典笔记；API 检查越权、重复请求、分页边界；worker 检查租约过期、重试、来源暂停与去重。测试种子包含空数据、中文长标题、缺省薪资、未知 DDL、过期岗位、慢响应与失败，不只验证顺畅路径。
