# 全功能本地版实施与验收

2026-10-23，用户授权：「继续，把除了数据之外的全部功能都完成」。沿用已确认的路由、视觉和交互设计；这一轮覆盖 MVP/V2/V3 的本地功能，不创建外部账号或接入真实招聘、云数据库、付费模型、转写与消息服务。

## 完成标准

- 页面上的新增、编辑、保存、发布、删除、筛选、排序、比较、练习、导出等操作产生实际结果，可刷新恢复；Toast 仅反馈结果。
- 33 个页面独立路由，导航、Drawer、命令搜索、收藏、投递、日程与相关知识联动。
- PDF/TXT 简历与录音在浏览器本地处理，二进制存 IndexedDB；不把大附件写入 localStorage。
- 未接模型的总结、诊断、评分按实际输入执行可解释的本地规则，明确标注规则分析；语音依浏览器支持降级，不能伪称云端 AI 或服务端转写。
- 桌面、平板、手机可操作；空输入、空列表、无权限、无浏览器能力、存储失败、无效链接均有处理。
- 生产构建、类型检查、领域规则测试、浏览器关键流程和全路由检查通过，实际证据写回交付状态。

## 共享接口约定

- `useLocal(key, initial)` 保留 tuple 接口，统一存储在 `radar-extended-${key}`；同页与跨标签更新通知，存储失败提示。
- Zustand `useRadarStore` 管理投递、收藏、个人资料与通知；Application 可选新增 resumeId、appliedAt、updatedAt、history，保持旧样本兼容。
- 私有云端资料继续使用独立 API 会话层；默认本地版不自动导入或上传其数据。API 模式中其他模块待接数据的状态不代表已经接入真实服务。
- 各模块的本地仓库提供读取/变化通知接口给全局搜索与收藏，不各自复制一份不可同步的条目。

## 本轮修复的关键边界

- 真实鼠标拖拽按指针所在列判定；避免空列较高时误入相邻阶段。
- 投递笔记使用版本条件写入，检测另一标签页更新时保留草稿，提供重新载入按钮。
- 日程读取与备份导入校验可选字段和 HTTP/HTTPS 链接；简历关联读取验证版本结构。
- PDF 校验 MIME 与文件头，使用 PDF.js Canvas 直接绘制，不依赖浏览器 PDF 插件。
- onboarding 多项写入失败回滚，发布/上传保存失败保留当前输入；完整备份恢复包含 IndexedDB 原件并在失败时撤回已写附件。
- 雷达 SVG title 改为单一文本，消除服务端和浏览器文本分段不同引起的 hydration 错误。
