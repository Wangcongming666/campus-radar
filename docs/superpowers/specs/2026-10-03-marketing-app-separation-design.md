# 官网与应用彻底分离设计（增强子项目 1c）

## 1. 文档目标

消除"官网首页"与"求职应用"的同页混合：`/` 永久只做企业官网，应用内不再保留带营销 Hero 的首页。这是 1b「双态首页」的后续修正——1b 让 `/` 在登录后变成应用首页，但该应用首页仍带营销式大标题与产品标语，观感上仍是"官网 + 功能"混排。

## 2. 定位与规则

- `/` = 企业官网介绍页，**对所有访问者**（含已登录）都只显示官网内容。不再有双态切换。
- 登录成功后直接进入**求职工作台** `/me/workspace`（应用的主入口），不再回到 `/`。
- 应用内**删除**原功能首页 `HomePage`（含 HeroSearch）：其"近期截止"能力由工作台「今日聚焦」的临期预警承载，搜索与职位浏览由 `/jobs` 承载，公司由 `/companies` 承载。
- 已登录用户在官网页（如点 logo 回到 `/`）看到的 CTA 是"进入求职工作台"，未登录看到"登录 / 注册"。
- 头部导航保持 1b 的双态：未登录 = logo + 登录入口；登录后 = 五个功能导航 + 昵称 + 退出（含窄屏导航内退出）。

## 3. 路由与守卫

- `/` 组件：`LandingPage`（不再经 HomeGate）。
- 守卫规则不变：仅 `/` 公开，其余路由要求登录；未登录访问 → 记录 returnTo 并回 `/`。
- 登录回跳：`returnTo ?? '/me/workspace'`。

## 4. 组件改动

- `LandingPage.vue`：CTA 依据会话状态渲染——已登录显示"进入求职工作台"（跳 `/me/workspace`），未登录显示"登录 / 注册"（触发登录框）。
- 删除 `HomeGate.vue`、`HomePage.vue`、`HeroSearch.vue` 及其测试 `HomeGate.test.ts`、`HeroSearch.test.ts`。

## 5. 测试

- `LandingPage` 组件测试：未登录 CTA 文案为"登录 / 注册"且点击触发登录；已登录 CTA 为"进入求职工作台"且跳转目标为 `/me/workspace`。
- 现有测试保持通过（删除 HomePage/HeroSearch/HomeGate 相关用例属预期减少）。

## 6. 验收要点

- 未登录与已登录访问 `/`，看到的都是企业官网介绍页（无求职功能内容、无 Hero 搜索框）。
- 登录成功后落在 `/me/workspace`；已登录在官网点 CTA 进入工作台。
- 应用内任何页面都不再出现"把复杂的校招，变成清晰的下一步"这类营销首屏。
- 四档宽度无遮挡；键盘可达。
