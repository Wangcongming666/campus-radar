# 启程校招产品与系统设计

## 1. 文档目标

本文定义“启程校招”首版的产品范围、交互原则、系统边界、数据模型和分阶段交付方式。当前先交付可独立运行和验收的前端，验收通过后再实现 Spring Boot 后端。前端 Mock API 的资源、字段、分页和错误结构与未来后端保持一致，后续替换数据源时不重写页面业务逻辑。

## 2. 产品定位

启程校招是一款面向中国大陆高校应届生的一站式求职 Web 平台，覆盖秋招、春招、提前批和补录。平台运营方人工维护企业和职位，支持 Excel 批量导入；学生在平台筛选机会、制作简历、阅读面试内容，并跳转企业官方渠道投递。

首版免费，不包含企业入驻、站内聊天、用户社区、实习、社会招聘、AI 润色、付费会员、广告排序和自动抓取。

## 3. 用户与权限

### 3.1 游客

游客可以访问首页、职位、公司和面试宝典。收藏、简历、投递记录、提醒和个人资料需要登录。公开内容使用稳定、可索引的 URL，便于分享和后续 SEO。

### 3.2 学生用户

学生通过邮箱验证码登录，可维护求职资料、收藏内容、制作简历、记录投递状态并设置提醒。首版不要求教育邮箱，避免排除已毕业但仍参与校招的用户。

### 3.3 内容运营

内容运营可以维护公司、职位、招聘批次和面试内容，执行 Excel 导入，查看普通用户基本状态，但不能创建其他管理员、修改系统安全配置或查看敏感认证数据。

### 3.4 超级管理员

超级管理员拥有内容运营的全部权限，并可管理运营账号、系统配置和审计日志。前端路由、菜单和操作按钮根据权限展示，后端阶段还会对每个接口独立鉴权。

## 4. 信息架构

### 4.1 学生端

- 首页：当前招聘季、全局职位搜索、近期截止、最新职位、热门公司、求职工具入口。
- 找职位：关键词搜索、筛选、排序、分页、收藏与清空筛选。
- 职位详情：职位信息、公司摘要、来源和更新时间、官方投递入口、相似职位。
- 公司库：公司搜索、行业和性质筛选、公司卡片。
- 公司详情：公司简介、基础信息、招聘官网、招聘批次和在招职位。
- 面试宝典：攻略文章和题库，按公司、岗位、行业、环节、难度和标签浏览。
- 简历中心：简历列表、创建、复制、重命名、编辑、预览、导出和删除。
- 投递看板：看板与列表视图，管理待确认、已投递、笔试、面试、Offer、拒绝和已结束。
- 个人中心：个人资料、收藏、浏览记录、通知、邮箱和账号安全。

### 4.2 运营后台

- 工作台：核心内容数量、即将截止职位、过期数据和待处理事项。
- 公司管理：新增、编辑、启停、Logo、官网和招聘官网。
- 职位管理：录入、编辑、复制、上下架、批量操作、Excel 导入与错误报告。
- 招聘批次：管理年份、类型、日期和状态。
- 面试内容：文章、题目、分类、标签、关联公司、发布与推荐。
- 用户管理：搜索、查看、禁用和恢复普通用户。
- 运营账号：超级管理员创建、停用和恢复内容运营账号。
- 系统配置：站点信息、导入模板说明和操作日志入口。

## 5. 关键用户流程

### 5.1 找职位并投递

1. 用户通过首页搜索或职位页筛选进入职位详情。
2. 点击“去官方投递”时，平台先创建状态为“待确认”的投递记录，再在新标签页打开企业官方链接。
3. 用户返回平台时看到非阻塞式确认提示，可标记“已完成投递”或“暂未投递”。
4. 用户在投递看板更新阶段、日期、备注和下一步提醒。
5. 职位过期或下架后不再进入默认搜索，但历史投递保存职位和公司的快照，仍可查看。

### 5.2 创建和导出简历

1. 用户选择模板并创建简历。
2. 编辑器以结构化表单维护基本信息、教育、实习、项目、技能、荣誉和自我评价。
3. 条目支持新增、删除、折叠和排序，桌面端实时显示分页预览。
4. 离开有未保存修改的页面前进行提示；自动保存失败时保留本地草稿并显示可恢复状态。
5. 用户通过浏览器打印能力导出 PDF，模板提供适合 A4 的打印样式。

### 5.3 Excel 导入职位

1. 运营人员下载模板或上传符合模板的 `.xlsx` 文件。
2. 前端检查文件类型、大小和必要列，展示解析进度。
3. 系统以表格展示有效行、警告和错误行，不直接写入正式数据。
4. 运营人员修正文件后重传，或确认导入全部有效行。
5. 导入完成后展示成功数、失败数和可下载的错误报告。

### 5.4 邮件提醒

用户可针对网申截止、笔试、面试或自定义事项设置提醒。提醒同时进入站内通知和邮件队列；发送失败会按有限次数重试，并保留失败原因。用户可取消未发送提醒，已发送记录不可重复触发。

## 6. 交互与视觉原则

视觉方向为“可信高效”：使用克制的蓝色作为主要强调色，以高可读性、清晰层级和适中的信息密度传达可靠与专业。品牌暂定“启程校招”，工程标识为 `career-launch`；名称、Logo 和主题令牌均可配置。

- 桌面端重点优化职位对比、简历编辑和后台表格；移动端重点优化浏览、收藏和投递状态更新。
- 公开页面从 320px 到桌面宽度响应式重排，不依赖横向滚动完成主要任务。
- 每个列表同时设计加载骨架、空状态、错误状态和无搜索结果状态。
- 危险操作使用明确的对象名称和二次确认；成功提示简短，不阻挡连续操作。
- 表单错误在字段附近解释原因，保留用户已输入内容，并把焦点移到第一个错误字段。
- 搜索筛选同步到 URL，刷新和分享链接后状态可恢复。
- 交互控件支持键盘操作、清晰焦点样式、语义化标签和足够点击区域；颜色不是唯一状态标识。
- 动效只用于状态过渡和层级提示，并遵循系统的减少动态效果设置。

## 7. 前端技术设计

### 7.1 工程结构

```text
career-launch/
├── apps/
│   ├── web/                 # 学生端 Vue 3 应用
│   └── admin/               # 运营后台 Vue 3 应用
├── packages/
│   ├── api-client/          # 请求客户端、DTO 与 Mock 适配器
│   ├── ui/                  # 两端共享的基础组件和设计令牌
│   └── shared/              # 枚举、校验器、格式化和通用工具
├── mocks/                   # 演示数据、请求处理器和数据重置能力
├── server/                  # 后端阶段使用的 Maven 多模块工程
├── deploy/                  # 本地与生产容器配置
└── docs/                    # 设计、接口、部署和运维文档
```

前端使用 Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus 和 pnpm workspace。学生端与后台共享基础组件和 API 类型，但不共享页面级业务组件，防止两个产品的交互约束互相污染。

### 7.2 Mock API

页面只能通过 `api-client` 访问数据，不直接读取 JSON 或浏览器存储。Mock 适配器模拟网络延迟、分页、校验错误、鉴权失败和偶发服务错误，并将用户操作持久化到 IndexedDB；提供“恢复演示数据”入口。

统一响应包含业务数据和请求追踪 ID。列表接口统一使用页码、每页数量、总数和数据数组。错误统一包含错误码、用户可读信息、字段错误和追踪 ID。未来接入后端时只替换客户端的传输适配器。

### 7.3 状态管理

- Pinia 保存登录会话、当前用户、全局字典和跨页面业务状态。
- 搜索条件、排序和分页保存在 URL 查询参数中。
- 页面内的临时表单和弹窗状态保持在组件内部。
- 服务端数据通过查询层缓存并失效，不重复复制到全局 Store。
- 登录凭据在后端阶段采用安全 Cookie；前端 Mock 只存无敏感价值的模拟会话标记。

### 7.4 简历预览与导出

简历数据和视觉模板分离，同一份数据可切换模板。预览使用独立渲染组件和 A4 尺寸规则；打印样式移除编辑控件、保留分页，并检查文本溢出。首版不实现自由画布和服务端 PDF。

## 8. 后端目标架构

后端阶段使用 Java 21、Spring Boot 3、Spring Security、MyBatis-Plus、Flyway、MySQL 8 和 Redis。应用采用模块化单体：`auth`、`user`、`recruitment`、`application`、`resume`、`knowledge`、`notification` 和 `infrastructure` 各自拥有清晰接口，不跨模块直接访问数据表。

文件存储采用 S3 兼容接口，本地使用 MinIO；邮件采用 SMTP，本地使用 Mailpit。接口通过 OpenAPI 描述并生成前端客户端。开发环境由 Docker Compose 一键启动，同时提供面向单机云服务器的生产容器、反向代理、环境变量、日志和备份说明。

## 9. 核心数据模型

- 用户：邮箱、昵称、头像、毕业年份、学校、学历、专业、求职方向、账号状态。
- 验证码：邮箱、用途、验证码哈希、过期时间、尝试次数和发送 IP。
- 管理员：用户引用、角色、安全状态和最后登录时间。
- 公司：名称、简称、Logo、行业、规模、性质、简介、官网、招聘官网、城市和状态。
- 招聘批次：年份、类型、开始日期、结束日期、展示名称和状态。
- 职位：公司、批次、名称、类别、城市、学历、专业要求、描述、投递地址、发布日期、截止时间、来源和状态。
- 导入任务：原文件、总行数、成功数、失败数、错误报告、执行人和状态。
- 投递记录：用户、职位引用、职位快照、当前阶段、投递时间、下一事件、备注和归档状态。
- 投递事件：阶段变化、发生时间和用户备注，组成不可覆盖的时间线。
- 简历：名称、模板、主题、状态和版本；教育、实习、项目、技能和荣誉为可排序的结构化条目。
- 文章与题目：标题、摘要、正文、分类、公司、难度、标签、发布状态、作者和发布时间。
- 收藏：用户、对象类型和对象 ID，使用唯一约束防止重复。
- 提醒：关联对象、提醒时间、渠道、发送状态和失败原因。
- 通知：标题、正文、业务类型、关联对象和已读状态。
- 审计日志：管理员、操作、对象、变更摘要、IP 和时间，不保存验证码等秘密。

数据库时间统一保存为 UTC，界面按 Asia/Shanghai 展示。业务记录优先软删除；职位下架不删除历史投递；用户注销冷静期结束后匿名化个人数据，依法需要的审计记录按规则保留。

## 10. 错误处理与安全

- 邮箱验证码按邮箱和 IP 限流，验证码只保存哈希，限制尝试次数并一次性使用。
- 管理后台与学生端使用独立路由保护；权限判断在未来后端接口中再次执行。
- 外部链接只允许 `http` 和 `https`，打开时防止新页面反向控制原页面。
- 富文本保存前后均进行白名单清洗，防止脚本注入。
- 文件上传校验扩展名、MIME、大小和文件头；对象存储使用随机键，不信任原文件名。
- Excel 导入设置行数与大小上限，公式按文本处理，不执行宏或外部引用。
- 客户端错误提示不展示堆栈、数据库信息或内部路径；追踪 ID 用于定位日志。
- 隐私相关页面明确数据用途、保存范围、导出和注销方式。

## 11. 性能与可运维性

- 页面和重型编辑器按路由拆包；图片懒加载并提供明确尺寸，避免布局跳动。
- 搜索输入防抖，筛选变更可取消过时请求；长列表采用服务端分页，不一次加载全部数据。
- 公开页面保留后续预渲染或服务端渲染的迁移空间，但前端首版使用 Vue SPA 交付。
- 生产环境配置健康检查、结构化日志、请求追踪 ID、数据库迁移和定期备份。
- 密钥只通过环境变量或密钥服务注入，不进入代码仓库和前端构建产物。

## 12. 验证策略

前端首次交付以可操作验收为主，同时执行必要的工程验证：

- TypeScript 严格类型检查。
- ESLint 与格式检查。
- 两个应用的生产构建。
- 共享校验器、状态转换和日期规则的单元测试。
- 关键页面在桌面与移动尺寸下的人工走查。
- 登录、搜索筛选、收藏、投递更新、简历编辑与导出、后台导入预览的验收清单。

依赖真实邮件、数据库和对象存储的集成测试放到后端阶段。后端阶段使用 JUnit 5、Testcontainers 和接口测试；系统完成后再补充 Playwright 端到端测试。

## 13. 分阶段交付

### 阶段一：前端完整体验

创建学生端、运营后台、共享组件、Mock API、演示数据和本地持久化，完成本文第 4 节列出的页面与第 5 节的前端交互。交付运行说明和验收清单。

### 阶段二：后端底座与招聘业务

实现认证、用户、权限、公司、职位、招聘批次、Excel 导入、收藏、投递和审计日志，替换对应 Mock 接口。

### 阶段三：简历与面试内容

实现简历持久化与版本、文件存储、面试文章和题库管理，替换剩余内容类 Mock 接口。

### 阶段四：通知、部署与系统验收

实现站内信、邮件提醒、定时任务、生产配置、备份恢复、监控与端到端测试，完成安全和性能验收。

## 14. 首版成功标准

- 新用户不需要帮助即可找到符合条件的职位，并理解职位来源与截止时间。
- 用户可从职位详情跳转官方投递，并在返回后完成投递记录确认。
- 用户可制作一份内容完整、无明显排版错误的 A4 PDF 简历。
- 用户可在投递看板中看清当前阶段、历史变化和下一项待办。
- 运营人员可通过表单和 Excel 维护职位，并在正式导入前发现错误数据。
- 学生端和后台在常见桌面与手机宽度下完成核心操作，无阻塞性布局问题。
