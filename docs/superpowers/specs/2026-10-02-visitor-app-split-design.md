# 企业官网与应用分域设计（增强子项目 1b）

## 1. 文档目标

把学生端拆成"双世界"：未登录访问看到的是**企业官网**（纯产品介绍站），登录后才是**应用**（现有全部功能）。解决当前官网与功能混在同一导航的问题。

## 2. 定位

- **官网（未登录）**：介绍"启程校招"是什么、给谁用、有哪些能力；底部联系方式；右上角登录/注册入口。不出现任何可进入功能的导航或入口。
- **应用（登录后）**：找职位、公司库、面试宝典、简历中心、求职工作台、个人中心，行为不变。
- 游客直接访问功能 URL：跳回官网首页并自动弹出登录框，登录成功后回到原目标页。

## 3. 路由与双态首页

- `/` 一个地址两种形态：`session.user` 为空渲染官网 `LandingPage.vue`；已登录渲染现有 `HomePage`（应用首页）。logo 始终链向 `/`。
- 功能路由路径全部不变（`/jobs`、`/companies`、`/knowledge`、`/me/*`），保持既有书签、通知 href、分享链接有效。
- 新增全局路由守卫 `requireAuth`：首次导航先 `await session.hydrate()`（一次性 ready 标志，防闪错），此后未登录访问非 `/` 路由 → 记录 `returnTo = to.fullPath` 并重定向 `/`，落地后弹出登录框。
- 登录成功：`router.push(returnTo ?? '/')`（既有 LoginDialog 行为，只需保证 `/` 已是应用形态）。
- 退出登录：清理会话后 `router.push('/')`，回到官网形态。

## 4. 布局

- 头部按登录态切换：未登录 = 官网头（AppLogo + 右上角"登录 / 注册"按钮）；已登录 = 应用头（找职位 / 公司库 / 面试宝典 / 简历中心 / 求职工作台 + 昵称链接 + **退出按钮**，退出需防误触确认）。窄屏菜单行为沿用。
- 官网页底部联系方式：演示邮箱 `hello@qicheng.example.com`、微信公众号文案、办公地点（虚构演示信息），加免责说明"演示环境"。

## 5. 官网页内容（介绍型）

- Hero：产品一句话定位 + 副文案 + "登录开始使用"CTA（触发登录框）。
- 三块能力介绍：职位与公司库、投递进度管理、简历工具——描述性卡片，不链接到功能页。
- 面向人群与使用场景（应届生、秋招/春招/提前批）。
- 联系方式页脚。

## 6. 数据与契约

不改动 `CareerRepository` 与领域模型。会话状态沿用 pinia `session` store（user/loginVisible/returnTo/hydrate/requestLogin/signedIn/logout）。

## 7. 人性化细节

- 登录框提示登录后"将回到你刚才想看的页面"。
- 退出确认文案说明后果（回到官网首页，数据保留）。
- 官网页与登录框全程键盘可达；`prefers-reduced-motion` 下无多余动画。
- hydrate 期间官网/应用形态不闪烁（守卫先等待会话就绪）。

## 8. 测试

- 守卫决策纯函数 `authRedirect(user, to)` 表驱动单测。
- `/` 双态切换：`HomeGate` 组件测试（mock pinia 会话）断言两种登录态渲染对应组件。
- 现有全部测试保持通过。

## 9. 验收要点

- 未登录访问 `/`：官网介绍页 + 底部联系方式 + 右上角登录入口，无功能导航。
- 未登录访问 `/me/workspace` 或 `/jobs`：跳回 `/` 且自动弹登录框；登录后回到目标页。
- 登录后 `/` 变为应用首页，头部出现五个功能导航 + 退出按钮。
- 退出登录后回到官网形态。
- 320/768/1024/1440 无遮挡，键盘可达。
